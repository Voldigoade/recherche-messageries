# Ricochet Refresh — dossier de preuves (situation au 13 octobre 2026)

!!! note "Registre de preuves — Phase 2"
    Ce dossier est une pièce de recherche datée. La [conclusion canonique](../resume.md) est celle du rapport final 1.0. Les synthèses antérieures et renvois à la Phase 3 restent historiques. `UNKNOWN` reste `UNKNOWN`.

**Séparation cruciale des versions.** Version stable Ricochet Refresh 3.0.46, publiée le 23 septembre 2026; elle embarque Tor 0.4.9.13. La branche maint-3.0 est la branche de release. Une 3.1.0-alpha.0 séparée expérimente une réécriture Rust du backend Tor/protocole et n’est pas traitée comme stable. Le Ricochet historique (v2 onion, dernier développement ancien) n’est pas Ricochet Refresh v3. L’audit NCC de 2015 porte sur le Ricochet historique, pas sur 3.0.46.

Sources primaires principales : [site et version 3.0.46](https://www.ricochetrefresh.net/), [release 3.0.46 / hashes / signatures / composants](https://github.com/blueprint-freespeech/ricochet-refresh/releases), [branche stable, code et historique](https://github.com/blueprint-freespeech/ricochet-refresh/tree/maint-3.0), [conception](https://github.com/blueprint-freespeech/ricochet-refresh/blob/main/doc/design.md), [protocole v3](https://github.com/blueprint-freespeech/ricochet-refresh/blob/maint-3.0/doc/protocol.md), [déclaration du projet sur les attaques médiatisées de 2019–2021](https://www.blueprintforfreespeech.net/en/news/statement-from-ricochet-refresh-regarding-recent-stories-in-german-medianbspabout-alleged-timing-attacks-affecting-our-users), [audit NCC original / PDF 24 pages](https://www.nccgroup.com/research/ricochet-security-assessment-public-report/), [miroir PDF lisible](https://roselabs.nl/files/audit_reports/NCC_Group_-_Ricochet.pdf), [registre australien Blueprint for Free Speech Inc.](https://abr.business.gov.au/ABN/View/38162740131).

### Ricochet Refresh — extraction du PDF NCC et limite de portée

**Organisme/commanditaire/version/méthode.** NCC Group Security Services, Inc.; projet Ricochet + Open Technology Fund; deux consultants à l’engagement, auteurs nommés Jesse Hertz, Patricio Jara-Ettinger, Mark Manning; rapport v1.2 du 15 février 2016. Le tableau de bord du PDF donne dates 16–22 novembre 2015 et 16 person-days; page OTF indique 16–25 novembre (écart de date documentaire). Source code review white-box C++, Qt, Protocol Buffers; revue de code et documents de design, fuzzing AFL et analyse dynamique qualifiée de cursory. Exclusions explicites: fichiers de layout QML hors périmètre; Tor lui-même hors périmètre; tests additionnels recommandés. Pas de hash commit/version source commitée dans le rapport; aucun retest NCC public trouvé.

### Ricochet Refresh — forensics et law enforcement

- **Forensics:** aucune étude publique de Cellebrite, GrayKey ou Magnet nommant Ricochet Refresh stable + version d’appareil, OS exact et date d’acquisition n’a été trouvée. Le profil ricochet.json et les clés onion locales sont une cible forensique évidente; c’est une inférence à partir de l’architecture, pas un test d’extraction testé. Les logs/chat history/caches de 3.0.46 doivent être examinés directement sur Windows/macOS/Linux, locked/unlocked et avec chiffrement disque activé/désactivé.
- **Affaire documentée:** enquêtes presse Panorama/STRG_F et Tagesschau (18 septembre 2024) sur Boystown rapportent que, pendant 2019–2021, le BKA/Généralstaatsanwaltschaft Frankfurt a utilisé une corrélation active de trafic Tor contre une cible utilisant Ricochet historique: activité de chat connue, observation de relais, découverte d’entry guards, puis ordonnance judiciaire au tribunal de Francfort demandant à Telefónica/O2 de retrouver les abonnés connectés à des nœuds identifiés. L’information effectivement obtenue rapportée est une attribution réseau/abonné par fournisseur télécom après corrélation; aucune remise de plaintext par Ricochet/Blueprint n’est décrite. Les articles s’appuient sur des pièces d’enquête, mais le dossier judiciaire complet et les données brutes de mesure ne sont pas publiés ici.
