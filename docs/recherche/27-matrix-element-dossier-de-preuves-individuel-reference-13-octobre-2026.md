# Matrix / Element — dossier de preuves individuel (référence : 13 octobre 2026)

!!! note "Registre de preuves — Phase 2"
    Ce dossier est une pièce de recherche datée. La [conclusion canonique](../resume.md) est celle du rapport final 1.0. Les synthèses antérieures et renvois à la Phase 3 restent historiques. `UNKNOWN` reste `UNKNOWN`.

**Périmètre.** Matrix est un protocole/API fédéré; un homeserver (Synapse ou autre) stocke et réplique l’état des salons; Element est un ensemble de clients et services d’hébergement, pas « le réseau Matrix ». La politique de matrix.org ne vaut que pour le homeserver matrix.org. Les données et garanties dépendent donc de l’opérateur, des réglages E2EE, des clients, des bridges et des services annexes. [Spécification Matrix](https://spec.matrix.org/v1.15/), [politique matrix.org](https://matrix.org/legal/privacy-notice/)

## Matrix / Element — repositories, builds et supply chain

- Dépôts principaux : [Synapse](https://github.com/element-hq/synapse), [Element Web](https://github.com/element-hq/element-web), [Element X Android](https://github.com/element-hq/element-x-android), [Element X iOS](https://github.com/element-hq/element-x-ios), [matrix-rust-sdk](https://github.com/matrix-org/matrix-rust-sdk), [vodozemac](https://github.com/matrix-org/vodozemac). Element Classic est à distinguer d’Element X.
- Les tags consultés sont signés/vérifiés GitHub et les workflows CI sont publics. Cela authentifie objets Git, pas identité binaire/source; aucune reproduction bit-à-bit d’APK, IPA ou desktop n’a été effectuée.
- Repositories exposent releases, CI, dependabot et advisories; nombre des mainteneurs actifs estimé sur une fenêtre trimestrielle non calculé. Les contributors d’une release ne sont qu’un proxy.
- Instance hébergée matrix.org est administrée opérationnellement par Element; ESS/EMS, push, LiveKit Cloud, MapTiler, analytics/crash et serveurs tiers créent des dépendances distinctes du code protocole.

## Matrix / Element — contradictions, zones inconnues, expériences à mener

- « Matrix est E2EE » est trop large : chiffrement par salon/client, optionnel dans le standard; salon non chiffré est lisible par homeservers.
- « Décentralisé donc sans point central » confond réseau et opération : un homeserver centralise les données de ses comptes; replication et federation ajoutent détenteurs/juridictions et empêchent d’assurer suppression globale.
- « Calls E2EE donc rien visible » est contredit par la politique Element Call, qui déclare IP, MXID/device, timestamps et type d’appel. Média et métadonnées sont deux couches.
- NCC 2016 findings de crypto/protocole, mitigations applicatives annoncées; formalisation 2024 montre dépendance aux signatures de préclés. Cela ne prouve ni vulnérabilité présente ni absence de vulnérabilité en release courante.
- BSI 2023 : le rapport décrit findings faibles; Element conteste certaines qualifications et annonce corrections. PDF BSI renvoie 403 ici, donc finding-level recoupé via l’éditeur, non lecture intégrale indépendante.
- Forensics 2026 : 175 tables concerne Synapse 1.133.0 de labo, pas un téléphone, pas outil commercial, pas disclosure à la police, et pas chaque déploiement. Paper distingue corps E2EE ciphertext de messages non chiffrés.
- Law enforcement : guide établit procédure/capacité, pas un cas de champs réellement remis. Cas documenté inconnu, pas preuve de non-remise.
- **Expériences nécessaires** : (1) payload APNs/FCM et analytics avec consentement sur builds exacts; (2) WebRTC direct vs TURN/SFU/IPv6; (3) build Store reproductible, manifests/entitlements/SDK/permissions; (4) tests de suppression, federation, retention/logs/media; (5) extraction forensique téléphone verrouillé/déverrouillé avec modèle+OS/build+Element+outil notés; (6) DNS/ASN/CDN passif horodaté; (7) cas judiciaire primaire montrant champs effectivement divulgués; (8) retest indépendant des fixes NCC/Least Authority/BSI sur commits actuels. Aucun test de cette liste n’est présenté comme réalisé.
